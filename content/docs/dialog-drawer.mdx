---
title: DialogDrawer
description: A centered Dialog at desktop that becomes a swipeable Drawer below 768px.
---

A drop-in replacement for the shadcn
[Dialog](https://ui.shadcn.com/docs/components/dialog): at 768px and up it
renders your Dialog unchanged; below, the same children render inside your
[Drawer](https://ui.shadcn.com/docs/components/drawer). The shared mechanism
(breakpoint, override prop, merge rules) is documented once in the
[Introduction](/docs).

## Usage

```tsx
import {
  DialogDrawer,
  DialogDrawerClose,
  DialogDrawerContent,
  DialogDrawerDescription,
  DialogDrawerFooter,
  DialogDrawerHeader,
  DialogDrawerTitle,
  DialogDrawerTrigger,
} from "@/components/ui/dialog-drawer"
```

```tsx
<DialogDrawer>
  <DialogDrawerTrigger>Open</DialogDrawerTrigger>
  <DialogDrawerContent>
    <DialogDrawerHeader>
      <DialogDrawerTitle>Title</DialogDrawerTitle>
      <DialogDrawerDescription>Description</DialogDrawerDescription>
    </DialogDrawerHeader>
    <DialogDrawerFooter>
      <DialogDrawerClose>Cancel</DialogDrawerClose>
    </DialogDrawerFooter>
  </DialogDrawerContent>
</DialogDrawer>
```

## Composition

```txt
DialogDrawer
├── DialogDrawerTrigger
└── DialogDrawerContent
    ├── DialogDrawerHeader
    │   ├── DialogDrawerTitle
    │   └── DialogDrawerDescription
    └── DialogDrawerFooter
        └── DialogDrawerClose
```

## Overriding the Drawer

Everything inside `drawer={{}}` is your installed Drawer's own API, for
example snap points on Base UI (see the Radix notes below for Vaul):

```tsx
<DialogDrawer
  drawer={{
    snapPoints: [0.5, 1],
    defaultSnapPoint: 0.5,
    showSwipeHandle: true,
  }}
>
  {/* … */}
</DialogDrawer>
```

## Sizing classes

The `className` on `DialogDrawerContent` applies to both sides. A width such
as `sm:max-w-sm`, from the shadcn Dialog examples, starts at 640px, below the
768px breakpoint, so it also narrows the drawer on large phones and small
tablets. Reset it in the override, or write the width with `md:`:

```tsx
<DialogDrawerContent
  className="sm:max-w-sm"
  drawer={{ className: "max-w-none" }}
>
```

## Body padding

The Dialog pads its whole content box; the Drawer pads only its header and
footer. Give the body between them its own padding below 768px:

```tsx
<DialogDrawerContent>
  <DialogDrawerHeader>{/* … */}</DialogDrawerHeader>
  <form className="grid gap-4 p-4 md:p-0">{/* … */}</form>
  <DialogDrawerFooter>{/* … */}</DialogDrawerFooter>
</DialogDrawerContent>
```

## Open state across the breakpoint

`DialogDrawer` holds the open state itself, so an uncontrolled dialog that is
open when the window crosses 768px stays open on the other side. `open`,
`defaultOpen` and `onOpenChange` work as they do on your Dialog. The content
remounts on the other side, so values held inside it, such as uncontrolled
form fields, reset: keep them in your own state or a form library if you need
them.

On the first render, before the viewport is known, the Dialog renders. A
`defaultOpen` dialog on a phone therefore shows briefly as a Dialog before it
becomes a Drawer. To open on load without that flash, control `open` and set
it after mount.

## `onOpenChange`

`onOpenChange` on the root has your Dialog's signature and also fires below
768px, so `onOpenChange={setOpen}` works on both sides. Below 768px it can
receive reasons only the Drawer has, such as `"swipe"`, which the Dialog's
types do not list. To act on them, use the Drawer's own handler, which runs
after the shared one:

```tsx
<DialogDrawer
  onOpenChange={setOpen}
  drawer={{
    onOpenChange: (open, eventDetails) => {
      if (eventDetails.reason === "swipe") {
        // below 768px only, after the shared handler
      }
    },
  }}
>
  {/* … */}
</DialogDrawer>
```

## Desktop-only props

These props apply at 768px and up and are dropped below:

- **`showCloseButton` on the Content.** A drawer has no close button in the
  corner; it closes on swipe or on an overlay tap. `showCloseButton` on the
  Footer works on both sides.
- **Detached triggers on Base UI:** `handle`, `triggerId` and
  `defaultTriggerId` on the root, `handle` and `payload` on the Trigger. Below
  768px, the drawer opens only from a `DialogDrawerTrigger` placed inside
  `DialogDrawer`, or from a controlled `open`.

A `className` function on a part receives your Dialog's state at desktop and
your Drawer's state below 768px.

## Nested dialogs

A `DialogDrawer` inside another one renders a drawer inside a drawer below
768px. On Base UI, your Drawer styles the parent as a stacked drawer while the
child is open.

## API reference

Each part takes every prop of its shadcn Dialog counterpart. The tables list
only what it adds.

### DialogDrawer

| Prop     | Type                                                         | Default |
| -------- | ------------------------------------------------------------ | ------- |
| `drawer` | `Omit<ComponentProps<typeof Drawer>, "children" \| RootState>` | -       |

`RootState` stands for the keys that `drawer` leaves out because they belong
to the shared root: `open` and `defaultOpen`, since both sides share one open
state, and the detached-trigger props `handle`, `triggerId` and
`defaultTriggerId`. `drawer.onOpenChange` runs after the shared
`onOpenChange` and receives your Drawer's own arguments.

### DialogDrawerTrigger

| Prop     | Type                                                                            | Default |
| -------- | ------------------------------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerTrigger>, "children" \| "handle" \| "payload">` | -       |

### DialogDrawerContent

| Prop     | Type                                                     | Default |
| -------- | -------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerContent>, "children">` | -       |

### DialogDrawerHeader

| Prop     | Type                                                    | Default |
| -------- | ------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerHeader>, "children">` | -       |

### DialogDrawerFooter

| Prop     | Type                                                    | Default |
| -------- | ------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerFooter>, "children">` | -       |

### DialogDrawerTitle

| Prop     | Type                                                   | Default |
| -------- | ------------------------------------------------------ | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerTitle>, "children">` | -       |

### DialogDrawerDescription

| Prop     | Type                                                         | Default |
| -------- | ------------------------------------------------------------ | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerDescription>, "children">` | -       |

### DialogDrawerClose

| Prop     | Type                                                   | Default |
| -------- | ------------------------------------------------------ | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerClose>, "children">` | -       |

## Radix notes

- `drawer={{}}` is typed on Vaul: `direction`, `dismissible`, `handleOnly`,
  `snapPoints`, the `onDrag` and `onRelease` callbacks, and so on. Vaul's
  `onOpenChange` receives only `open`, with no reason.
- Like Radix Dialog, the drawer moves focus inside when it opens. Pass
  `drawer={{ autoFocus: false }}` to keep Vaul's own default.
- Vaul nests drawers through `Drawer.NestedRoot`, which your shadcn Drawer
  does not export: a nested `DialogDrawer` opens a second drawer on top,
  without Vaul's nested-drawer styling.
- Vaul, the drawer library under the Radix Drawer, is no longer maintained
  upstream. It still works; the Base UI Drawer is the maintained option.
