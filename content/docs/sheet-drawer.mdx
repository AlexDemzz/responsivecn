A drop-in replacement for the shadcn
[Sheet](https://ui.shadcn.com/docs/components/sheet): at 768px and up it
renders your Sheet unchanged; below, the same children render inside your
[Drawer](https://ui.shadcn.com/docs/components/drawer), anchored to the same
edge. The shared mechanism (breakpoint, override prop, merge rules) is
documented once in the [Introduction](/docs).

## Usage

```tsx
import {
  SheetDrawer,
  SheetDrawerClose,
  SheetDrawerContent,
  SheetDrawerDescription,
  SheetDrawerFooter,
  SheetDrawerHeader,
  SheetDrawerTitle,
  SheetDrawerTrigger,
} from "@/components/ui/sheet-drawer"
```

```tsx
<SheetDrawer>
  <SheetDrawerTrigger>Open menu</SheetDrawerTrigger>
  <SheetDrawerContent side="right">
    <SheetDrawerHeader>
      <SheetDrawerTitle>Title</SheetDrawerTitle>
      <SheetDrawerDescription>Description</SheetDrawerDescription>
    </SheetDrawerHeader>
    <SheetDrawerFooter>
      <SheetDrawerClose>Close</SheetDrawerClose>
    </SheetDrawerFooter>
  </SheetDrawerContent>
</SheetDrawer>
```

## Composition

```txt
SheetDrawer
├── SheetDrawerTrigger
└── SheetDrawerContent
    ├── SheetDrawerHeader
    │   ├── SheetDrawerTitle
    │   └── SheetDrawerDescription
    └── SheetDrawerFooter
        └── SheetDrawerClose
```

## The drawer edge

The Sheet sets its edge with `side` on the Content; the Drawer sets it on the
root, where it also drives the swipe gesture. `SheetDrawerContent` passes its
`side` up to the root, so below 768px the drawer opens from the same edge and
swipes the same way. This works wherever the Content sits: inside a Fragment,
behind a condition or in your own component.

```tsx
<SheetDrawer>
  <SheetDrawerTrigger>Open menu</SheetDrawerTrigger>
  {/* a left Sheet at desktop, a left Drawer below 768px */}
  <SheetDrawerContent side="left">{/* … */}</SheetDrawerContent>
</SheetDrawer>
```

Without `side`, each component keeps its own default: the Sheet opens from
the right, the Drawer from the bottom. Write `side="right"` to get a right
drawer too.

To pick another edge on mobile only, set it on the root override. It wins
over `side`:

```tsx
<SheetDrawer drawer={{ swipeDirection: "down" }}>
  {/* a left Sheet at desktop, a bottom Drawer below 768px */}
  <SheetDrawerContent side="left">{/* … */}</SheetDrawerContent>
</SheetDrawer>
```

## Sizing classes

The `className` on `SheetDrawerContent` applies to both sides. A width such as
`w-[400px] sm:w-[540px]` therefore also narrows a bottom drawer. Reset it in
the override, or scope the width to desktop with `md:`:

```tsx
<SheetDrawerContent
  className="w-[400px] sm:w-[540px]"
  drawer={{ className: "w-auto" }}
>
```

## Open state across the breakpoint

`SheetDrawer` holds the open state itself, so an uncontrolled sheet that is
open when the window crosses 768px stays open on the other side. `open`,
`defaultOpen` and `onOpenChange` work as they do on your Sheet. Form values
held inside the content still reset: lift them into your own state if you
need to keep them.

On the first render, before the viewport is known, the Sheet renders. A
`defaultOpen` sheet on a phone therefore shows briefly as a Sheet before it
becomes a Drawer. To open on load without that flash, control `open` and set
it after mount.

## Desktop-only props

These props apply at 768px and up and are dropped below:

- **`showCloseButton` on the Content.** A drawer has no close button in the
  corner; it closes on swipe or on an overlay tap. If the built-in button is
  your only way to close the sheet, add a `SheetDrawerClose`.
- **Detached triggers on Base UI:** `handle`, `triggerId` and
  `defaultTriggerId` on the root, `handle` and `payload` on the Trigger. Below
  768px, the drawer opens only from a `SheetDrawerTrigger` placed inside
  `SheetDrawer`.

## Nested sheets

A `SheetDrawer` inside another one renders a drawer inside a drawer below
768px. On Base UI, your Drawer styles the parent as a stacked drawer while the
child is open.

## API reference

Each part takes every prop of its shadcn Sheet counterpart. The tables list
only what it adds.

### SheetDrawer

| Prop     | Type                                                           | Default |
| -------- | -------------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof Drawer>, "children" \| RootState>` | -       |

`RootState` stands for the keys that `drawer` leaves out because they belong
to the shared root: `open` and `defaultOpen`, since both sides share one open
state, and the detached-trigger props `handle`, `triggerId` and
`defaultTriggerId`. `drawer.onOpenChange` runs after the shared
`onOpenChange` and receives your Drawer's own arguments, such as a `"swipe"`
reason on Base UI.

### SheetDrawerTrigger

| Prop     | Type                                                                              | Default |
| -------- | --------------------------------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerTrigger>, "children" \| "handle" \| "payload">` | -       |

### SheetDrawerContent

| Prop     | Type                                                     | Default |
| -------- | -------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerContent>, "children">` | -       |

### SheetDrawerHeader

| Prop     | Type                                                    | Default |
| -------- | ------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerHeader>, "children">` | -       |

### SheetDrawerFooter

### SheetDrawerTitle

## Radix notes

- `drawer={{}}` is typed on Vaul. The mobile-only edge is
  `drawer={{ direction }}`, which takes the same four values as `side`.
- Like Radix Dialog, the drawer moves focus inside when it opens. Pass
  `drawer={{ autoFocus: false }}` to keep Vaul's own default.
- Vaul nests drawers through `Drawer.NestedRoot`, which your shadcn Drawer
  does not export: a nested `SheetDrawer` opens a second drawer on top,
  without Vaul's nested-drawer styling.
- Vaul, the drawer library under the Radix Drawer, is no longer maintained
  upstream. It still works; the Base UI Drawer is the maintained option.
