A drop-in replacement for the shadcn
[Sheet](https://ui.shadcn.com/docs/components/sheet): at 768px and up it
renders the Sheet unchanged; below, the same children render inside a
[Drawer](https://ui.shadcn.com/docs/components/drawer). The shared mechanism —
breakpoint, override prop, merge rules, state loss — is documented once in the
[Introduction](/docs).

## `side` and the swipe direction

This pair's specific problem: the Sheet's `side` is a CSS-only prop on the
**Content**, while the Drawer's direction is a **Root** prop that drives
gesture physics. When you set `side` explicitly on `SheetDrawerContent`, the
root picks it up and maps it onto the mobile Drawer, so the drawer anchors to
the same edge and swipes accordingly:

<Tabs groupId="base" persist items={["Base UI", "Radix"]}>

<Tab>

A fixed lookup maps `side` to the Base UI Drawer's `swipeDirection`:
`top → "up"`, `right → "right"`, `bottom → "down"`, `left → "left"`.

```tsx
<SheetDrawer>
  <SheetDrawerTrigger>Open menu</SheetDrawerTrigger>
  {/* Sheet from the left at desktop, left-swiping Drawer below 768px */}
  <SheetDrawerContent side="left">{/* … */}</SheetDrawerContent>
</SheetDrawer>
```

An explicit `drawer={{ swipeDirection }}` on the root wins over the
side-derived value:

```tsx
<SheetDrawer drawer={{ swipeDirection: "down" }}>
  {/* left Sheet at desktop, bottom Drawer on mobile anyway */}
  <SheetDrawerContent side="left">{/* … */}</SheetDrawerContent>
</SheetDrawer>
```

</Tab>

<Tab>

On Radix the mapping is the identity: `side` forwards to Vaul's `direction`
prop, which names the anchored edge with the same four values.

```tsx
<SheetDrawer>
  <SheetDrawerTrigger>Open menu</SheetDrawerTrigger>
  {/* Sheet from the left at desktop, left-anchored Vaul drawer below 768px */}
  <SheetDrawerContent side="left">{/* … */}</SheetDrawerContent>
</SheetDrawer>
```

An explicit `drawer={{ direction }}` on the root wins over the side-derived
value:

```tsx
<SheetDrawer drawer={{ direction: "bottom" }}>
  <SheetDrawerContent side="left">{/* … */}</SheetDrawerContent>
</SheetDrawer>
```

</Tab>

</Tabs>

Two rules to keep in mind:

- **No auto-map when `side` is unset.** Each side keeps its native default —
  the Sheet opens from the right, the drawer from the bottom. The two are
  intentionally divergent: a bottom drawer is the natural mobile default, and
  masking native defaults is exactly what this project
  [does not do](/docs#the-override-prop).
- **`side` is read from the root's direct children.** `SheetDrawerContent`
  must be a direct child of `SheetDrawer` for the mapping to apply — wrap it
  in your own component and the root cannot see the prop, so the mobile
  drawer silently falls back to the bottom. Set
  `drawer={{ swipeDirection }}` (Radix: `drawer={{ direction }}`) on the root
  in that case.

## Not in v1

- **`handle` / `triggerId`** (Base UI): `Dialog.Handle` and `Drawer.Handle`
  are distinct classes — a desktop handle cannot drive the mobile primitive,
  so detached triggers are dropped from this pair.
- **`showCloseButton` below the breakpoint**: the prop is desktop-only — a
  drawer dismisses by swipe. It keeps working at 768px and up.

## Radix notes

<Callout type="warn" title="Radix notes">

- **Vaul is unmaintained.** It is the mobile side of this pair on Radix —
  choose the `-radix` variant knowingly.
- `side` maps to Vaul's `direction` (identity — same four values), and the
  mobile override is `drawer={{ direction }}`, not `swipeDirection`. The
  override contract is name parity with the Base UI item, typed 1:1 on Vaul's
  own API.
- **Focus**: the Radix Sheet moves focus into the popup on open; Vaul
  suppresses it by default. Pass `drawer={{ autoFocus: true }}` — without it
  the focused trigger ends up behind `aria-hidden` and the console logs a
  focus-trap/aria-hidden error.

</Callout>
