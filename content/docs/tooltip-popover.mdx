title: TooltipPopover
description: A hover Tooltip at desktop that becomes a press-to-open Popover below 768px.

A drop-in replacement for the shadcn
[Tooltip](https://ui.shadcn.com/docs/components/tooltip): at 768px and up it
renders the Tooltip unchanged; below, the same children render inside a
[Popover](https://ui.shadcn.com/docs/components/popover). This pair exists
because **hover does not exist on touch** — a tooltip is simply dead under a
finger, and swapping it for a press-to-open popover is the fix Base UI itself
prescribes. The shared mechanism — breakpoint, override prop, merge rules,
state loss — is documented once in the [Introduction](/docs).

## The override prop is `popover={{}}`

The override prop is named after the mobile side of the pair — here that is
the Popover, so this is the one pair whose override is `popover={{}}` rather
than `drawer={{}}`:

<Tabs groupId="base" persist items={["Base UI", "Radix"]}>

<Tab>

```tsx
<TooltipPopover popover={{ modal: true }}>
  <TooltipPopoverTrigger popover={{ openOnHover: true }}>
    Info
  </TooltipPopoverTrigger>
  <TooltipPopoverContent popover={{ side: "bottom", sideOffset: 8 }}>
    {/* … */}
  </TooltipPopoverContent>
</TooltipPopover>
```

`popover={{ openOnHover: true }}` on the Trigger opts the mobile Popover into
hover-opening on hybrid devices — Base UI's own infotip recommendation.

</Tab>

<Tab>

```tsx
<TooltipPopover popover={{ modal: true }}>
  <TooltipPopoverTrigger>Info</TooltipPopoverTrigger>
  <TooltipPopoverContent popover={{ side: "bottom", sideOffset: 8 }}>
    {/* … */}
  </TooltipPopoverContent>
</TooltipPopover>
```

No `openOnHover` here: the Radix Popover trigger is click-only, so the mobile
side is strictly press-to-open.

</Tab>

</Tabs>

One consequence of claiming that name: `popover` is also a native HTML global
attribute (the Popover API — `popover="auto"`). The parts drop the native
attribute in favour of the override namespace, so you cannot pass the HTML
`popover` attribute through this component.

## Title and Description

The Tooltip primitive has no Title or Description parts — a tooltip is a
transient hint, not a labelled surface. `TooltipPopoverTitle` and
`TooltipPopoverDescription` are therefore this pair's fallback parts: at
desktop they render as plain styled elements (never `null`), and below the
breakpoint they become the real `PopoverTitle` and `PopoverDescription`,
giving touch users the accessible structure a tooltip cannot provide.

## TooltipProvider

`TooltipProvider` stays the app-level shadcn convention: keep one at the root
of your app for instant, grouped tooltips at desktop. It is optional for
correctness — without it the Tooltip works with Base UI's default 600ms
delay — and it renders no DOM, so it is harmless around the mobile Popover
branch.

## Placement defaults

When `side` is unset on the Content, each side keeps its native default: the
Tooltip opens on **top**, the Popover on the **bottom**. As everywhere else,
native defaults are respected rather than masked — set `side` explicitly (or
`popover={{ side }}` for mobile only) if you need both to match.

## Accessibility

Give an icon-only trigger an `aria-label` that matches the content — the
trigger is a plain button on both sides, and below the breakpoint nothing
opens until it is pressed, so the label is all a screen reader gets up front:

```tsx
<TooltipPopoverTrigger aria-label="About response rate">
  <InfoIcon />
</TooltipPopoverTrigger>
```

## Radix notes

<Callout type="warn" title="Radix notes">

- **Radix tooltips are touch-dead by design** — the trigger ignores touch
  pointers and a tap closes an open tooltip. Radix documents no alternative;
  the tooltip→popover swap is responsivecn's own prescription on this base.
- **The swap is structural, not an a11y upgrade.** The Radix-flavor shadcn
  `PopoverTitle`/`PopoverDescription` are bare styled `<div>`s with no aria
  wiring — unlike Base UI, where the mobile side upgrades to real accessible
  parts. The `aria-label` advice above matters all the more here.
- **No hover-open on the mobile Popover.** The Radix Popover trigger is
  click-only — there is no `openOnHover` opt-in as on Base UI. Desktop is
  hover-tooltip, mobile is press-popover, strictly.

</Callout>
