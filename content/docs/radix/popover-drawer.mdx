A drop-in replacement for the shadcn
[Popover](https://ui.shadcn.com/docs/components/popover): at 768px and up it
renders the Popover unchanged; below, the same children render inside a
[Drawer](https://ui.shadcn.com/docs/components/drawer). The shared mechanism —
breakpoint, override prop, merge rules, state loss — is documented once in the
[Introduction](/docs). Resize the window across 768px and reopen it to see the
swap.

## Usage

```tsx
import {
  PopoverDrawer,
  PopoverDrawerContent,
  PopoverDrawerDescription,
  PopoverDrawerFooter,
  PopoverDrawerHeader,
  PopoverDrawerTitle,
  PopoverDrawerTrigger,
} from "@/components/ui/popover-drawer"
```

```tsx
<PopoverDrawer>
  <PopoverDrawerTrigger>Filters</PopoverDrawerTrigger>
  <PopoverDrawerContent>
    <PopoverDrawerHeader>
      <PopoverDrawerTitle>Filters</PopoverDrawerTitle>
      <PopoverDrawerDescription>Narrow down the results.</PopoverDrawerDescription>
    </PopoverDrawerHeader>
    <PopoverDrawerFooter>
      <button type="button">Apply</button>
    </PopoverDrawerFooter>
  </PopoverDrawerContent>
</PopoverDrawer>
```

```txt
PopoverDrawer
├── PopoverDrawerTrigger
└── PopoverDrawerContent
    ├── PopoverDrawerHeader
    │   ├── PopoverDrawerTitle
    │   └── PopoverDrawerDescription
    └── PopoverDrawerFooter
```

## The `modal` divergence

This is the one pair whose two sides disagree on modality: a Popover is
**non-modal** by default, a Drawer is **modal** by default. `PopoverDrawer`
does not mask that — with no `modal` prop, the same component is a
light-dismiss anchored popover at desktop and a modal drawer with an overlay
below 768px. That is each side's native, expected behaviour.

Set `modal` explicitly and it forwards to **both** sides; use the override
prop to target only the mobile drawer:

```tsx
{/* explicit modal → forwarded to both Popover and Drawer */}
<PopoverDrawer modal>{/* … */}</PopoverDrawer>

{/* native defaults on desktop, non-modal drawer on mobile only */}
<PopoverDrawer drawer={{ modal: false }}>{/* … */}</PopoverDrawer>
```

A non-modal Vaul drawer stays open when you tap outside it, where the
non-modal Popover it replaces light-dismisses — the two non-modal behaviours
differ in kind, not just in styling.

## The Footer part

The shadcn Popover ships no footer, but the Drawer's action row is where
mobile buttons belong. `PopoverDrawerFooter` fills the gap: at desktop it is a
plain styled `<div>` (a functional fallback — never `null`, so your markup
survives the viewport change); below the breakpoint it is the real
`DrawerFooter`.

There is no Close part on this pair — the Popover has none (it light-dismisses
on outside click), and the drawer dismisses by swipe.

## Desktop-only props

Positioning props on the Content — `side`, `align`, `sideOffset`,
`alignOffset`, and the whole Popper surface (`avoidCollisions`,
`collisionBoundary`, `collisionPadding`, `arrowPadding`, `sticky`,
`hideWhenDetached`, `updatePositionStrategy`) — are anchor positioning, which
is meaningless on an edge-anchored drawer. They apply at 768px and up and are
silently dropped below.

`PopoverAnchor` is not part of this pair: the Radix shadcn Popover exports it,
but anchoring has no drawer analog, so it is dropped.
