A drop-in replacement for the shadcn
[Tooltip](https://ui.shadcn.com/docs/components/tooltip): at 768px and up it
renders the Tooltip unchanged; below, the same children render inside a
[Popover](https://ui.shadcn.com/docs/components/popover). This pair exists
because **hover does not exist on touch** — a Radix tooltip is dead under a
finger (the trigger ignores touch pointers, and a tap closes an open tooltip),
so swapping it for a press-to-open popover is the fix. The shared mechanism —
breakpoint, override prop, merge rules, state loss — is documented once in the
[Introduction](/docs). Resize the window across 768px to see the swap.

## Usage

```tsx
import {
  TooltipPopover,
  TooltipPopoverContent,
  TooltipPopoverDescription,
  TooltipPopoverTitle,
  TooltipPopoverTrigger,
} from "@/components/ui/tooltip-popover"
```

```tsx
<TooltipPopover>
  <TooltipPopoverTrigger aria-label="About response rate">
    <InfoIcon />
  </TooltipPopoverTrigger>
  <TooltipPopoverContent>
    <TooltipPopoverTitle>Response rate</TooltipPopoverTitle>
    <TooltipPopoverDescription>The share of messages you reply to within 24 hours.</TooltipPopoverDescription>
  </TooltipPopoverContent>
</TooltipPopover>
```

## Composition

```txt
TooltipPopover
├── TooltipPopoverTrigger
└── TooltipPopoverContent
    ├── TooltipPopoverTitle
    └── TooltipPopoverDescription
```

## The override prop is `popover={{}}`

The override prop is named after the mobile side of the pair — here that is
the Popover, so this is the one pair whose override is `popover={{}}` rather
than `drawer={{}}`:

```tsx
<TooltipPopover popover={{ modal: true }}>
  <TooltipPopoverTrigger>Info</TooltipPopoverTrigger>
  <TooltipPopoverContent popover={{ side: "bottom", sideOffset: 8 }}>
    {/* … */}
  </TooltipPopoverContent>
</TooltipPopover>
```

The Radix Popover trigger is click-only, so the mobile side is strictly
press-to-open — there is no `openOnHover` opt-in.

One consequence of claiming that name: `popover` is also a native HTML global
attribute (the Popover API — `popover="auto"`). The parts drop the native
attribute in favour of the override namespace, so you cannot pass the HTML
`popover` attribute through this component.

## Title and Description

The Tooltip primitive has no Title or Description parts — a tooltip is a
transient hint, not a labelled surface. `TooltipPopoverTitle` and
`TooltipPopoverDescription` are this pair's fallback parts: at desktop they
render as plain styled elements (never `null`), and below the breakpoint they
become the real `PopoverTitle` and `PopoverDescription`. On Radix these are
bare styled `<div>`s with no aria wiring, so the `aria-label` advice below
carries the accessible name.

## TooltipProvider

`TooltipProvider` stays the app-level shadcn convention: keep one at the root
of your app for instant, grouped tooltips at desktop. It renders no DOM, so it
is harmless around the mobile Popover branch.

## Placement defaults

When `side` is unset on the Content, each side keeps its native default: the
Tooltip opens on **top**, the Popover on the **bottom**. As everywhere else,
native defaults are respected rather than masked — set `side` explicitly (or
`popover={{ side }}` for mobile only) if you need both to match.

## Accessibility

Give an icon-only trigger an `aria-label` that matches the content — the
trigger is a plain button on both sides, and below the breakpoint nothing
opens until it is pressed, so the label is all a screen reader gets up front:

```tsx
<TooltipPopoverTrigger aria-label="About response rate">
  <InfoIcon />
</TooltipPopoverTrigger>
```
