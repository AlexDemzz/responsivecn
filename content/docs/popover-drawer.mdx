A drop-in replacement for the shadcn
[Popover](https://ui.shadcn.com/docs/components/popover): at 768px and up it
renders your Popover unchanged; below, the same children render inside your
[Drawer](https://ui.shadcn.com/docs/components/drawer). The shared mechanism
(breakpoint, override prop, merge rules) is documented once in the
[Introduction](/docs).

## Usage

```tsx
import {
  PopoverDrawer,
  PopoverDrawerContent,
  PopoverDrawerDescription,
  PopoverDrawerHeader,
  PopoverDrawerTitle,
  PopoverDrawerTrigger,
} from "@/components/ui/popover-drawer"
```

```tsx
<PopoverDrawer>
  <PopoverDrawerTrigger>Open popover</PopoverDrawerTrigger>
  <PopoverDrawerContent>
    <PopoverDrawerHeader>
      <PopoverDrawerTitle>Title</PopoverDrawerTitle>
      <PopoverDrawerDescription>Description</PopoverDrawerDescription>
    </PopoverDrawerHeader>
  </PopoverDrawerContent>
</PopoverDrawer>
```

## Composition

```txt
PopoverDrawer
├── PopoverDrawerAnchor (Radix, optional)
├── PopoverDrawerTrigger
└── PopoverDrawerContent
    ├── PopoverDrawerHeader
    │   ├── PopoverDrawerTitle
    │   └── PopoverDrawerDescription
    └── PopoverDrawerFooter (optional)
```

## The content box

Below 768px, `PopoverDrawerContent` wraps its children in a padded box with
the Popover's column layout, so children written for the Popover render the
same way in the Drawer. The `className` you pass to `PopoverDrawerContent`
styles that box; `drawer={{ className }}` styles the drawer itself:

```tsx
<PopoverDrawerContent className="w-80" drawer={{ className: "max-h-[80dvh]" }}>
```

A width such as `w-80` therefore sizes the content, centered in a full-width
drawer, instead of shrinking the drawer to a 320px panel.
`PopoverDrawerHeader` and `PopoverDrawerFooter` take their spacing from that
box, as they do in the Popover.

## Open state across the breakpoint

`PopoverDrawer` holds the open state itself, so an uncontrolled popover that
is open when the window crosses 768px stays open on the other side. `open`,
`defaultOpen` and `onOpenChange` work as they do on your Popover. Form values
held inside the content still reset: lift them into your own state if you
need to keep them.

## The `modal` default

A Popover is non-modal by default; a Drawer is modal. With no `modal` prop,
each side keeps its own default: an anchored popover that closes on an outside
click at desktop, a drawer with an overlay below 768px. Set `modal` to apply
it to both sides, or `drawer={{ modal }}` to change only the drawer:

```tsx
<PopoverDrawer drawer={{ modal: false }}>
```

## The Footer part

The shadcn Popover has no footer, but a drawer needs an action row.
`PopoverDrawerFooter` is optional: a `flex justify-end gap-2` row at desktop,
your `DrawerFooter` below 768px.

To close from a button inside the content, control `open`, as you would with
the Popover:

```tsx
const [open, setOpen] = React.useState(false)

<PopoverDrawer open={open} onOpenChange={setOpen}>
  <PopoverDrawerTrigger>Filters</PopoverDrawerTrigger>
  <PopoverDrawerContent>
    {/* … */}
    <PopoverDrawerFooter>
      <button type="button" onClick={() => setOpen(false)}>
        Apply
      </button>
    </PopoverDrawerFooter>
  </PopoverDrawerContent>
</PopoverDrawer>
```

## Desktop-only props

These props apply at 768px and up and are dropped below, because a drawer has
no equivalent:

- **Positioning on the Content:** `side`, `align`, `sideOffset`,
  `alignOffset`, and on Radix the rest of the Popper props
  (`avoidCollisions`, `collisionPadding`, `sticky`, …).
- **Hover on the Trigger:** `openOnHover`, `delay`, `closeDelay`.
- **Detached triggers on Base UI:** `handle`, `triggerId` and
  `defaultTriggerId` on the root, `handle` and `payload` on the Trigger. Below
  768px, the drawer opens only from a `PopoverDrawerTrigger` placed inside
  `PopoverDrawer`.
- **Anchoring on Radix:** `PopoverDrawerAnchor` renders your `PopoverAnchor`
  at desktop. Below 768px it renders its child (with `asChild`) or a plain
  `div`.

## Accessibility

Below 768px the content is a dialog, and a dialog needs a name. A popover
without a title gets none: add a `PopoverDrawerTitle`, visually hidden if the
design has no heading.

```tsx
<PopoverDrawerTitle className="sr-only">Filters</PopoverDrawerTitle>
```

## API reference

Each part takes every prop of its shadcn Popover counterpart. The tables list
only what it adds.

### PopoverDrawer

| Prop     | Type                                                           | Default |
| -------- | -------------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof Drawer>, "children" \| RootState>` | -       |

`RootState` stands for the keys that `drawer` leaves out because they belong
to the shared root: `open` and `defaultOpen`, since both sides share one open
state, and the detached-trigger props `handle`, `triggerId` and
`defaultTriggerId`. `drawer.onOpenChange` runs after the shared
`onOpenChange` and receives your Drawer's own arguments.

### PopoverDrawerTrigger

| Prop     | Type                                                                              | Default |
| -------- | --------------------------------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerTrigger>, "children" \| "handle" \| "payload">` | -       |

### PopoverDrawerContent

| Prop     | Type                                                     | Default |
| -------- | -------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerContent>, "children">` | -       |

### PopoverDrawerHeader

| Prop     | Type                                                    | Default |
| -------- | ------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerHeader>, "children">` | -       |

### PopoverDrawerTitle

| Prop     | Type                                                   | Default |
| -------- | ------------------------------------------------------ | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerTitle>, "children">` | -       |

### PopoverDrawerDescription

| Prop     | Type                                                         | Default |
| -------- | ------------------------------------------------------------ | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerDescription>, "children">` | -       |

### PopoverDrawerFooter

Takes every prop of a `div`.

| Prop     | Type                                                    | Default |
| -------- | ------------------------------------------------------- | ------- |
| `drawer` | `Omit<ComponentProps<typeof DrawerFooter>, "children">` | -       |

### PopoverDrawerAnchor

Radix only. Takes every prop of your `PopoverAnchor` and adds none.

## Radix notes

- `drawer={{}}` is typed on Vaul: `direction`, `dismissible`, `snapPoints`,
  and so on.
- Like Radix Popover, the drawer moves focus inside when it opens. Pass
  `drawer={{ autoFocus: false }}` to keep Vaul's own default.
- A non-modal Vaul drawer stays open when you tap outside it, unlike the
  non-modal Popover. Control `open` to close it from inside.
- Vaul, the drawer library under the Radix Drawer, is no longer maintained
  upstream. It still works; the Base UI Drawer is the maintained option.
